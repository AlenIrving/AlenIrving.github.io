APC注入

这里复现的是Early Bird APC 注入，属于APC的一种

OpenProcess -> VirtualAllocEx -> WriteProcessMemory -> CreateToolhelp32Snapshot (枚举线程) -> OpenThread -> QueueUserAPC

如果把程序的运行比作一家正在营业的餐厅：

APC机制就像是餐厅里的“服务员传呼系统”。
正常情况下，厨师（程序主线程）正在炒菜时，是不会理会传呼机的。只有当厨师做完一道菜，主动按下“空闲”按钮（进入可警告状态，如调用 SleepEx）时，他才会去查看传呼机里有没有经理留下的新指令（APC队列）。

经典APC注入就像是黑客偷偷溜进后厨，往传呼机里塞了一张写着“把毒药倒进汤里”的纸条。
痛点在于：如果厨师一直忙个不停，或者压根不看传呼机，这张纸条就一直躺在那儿，黑客的阴谋就无法得逞，全看运气。

Early Bird APC注入则是黑客利用了“餐厅刚开业”的漏洞。
黑客趁餐厅大门还没开、厨师刚换好衣服还没开始干活时（进程挂起状态），就提前把“毒药纸条”塞进了传呼机。
因为餐厅有个死规矩：厨师在正式开火炒菜前，必须先检查一遍传呼机有没有开业通知（系统强制调用 NtTestAlert）。
结果就是，厨师刚上岗，100%会立刻看到并执行黑客的纸条，而此时餐厅的保安（杀毒软件）甚至还没打卡上班呢！

消息钩取注入

LoadLibraryA (安装器加载 HookDll) -> GetProcAddress (取 InstallHook 地址) -> InstallHook() -> SetWindowsHookExA (安装全局钩子) -> 系统在目标进程回调 KeyboardProc (DLL 被强制加载)

你连大楼都不进，只是在大楼入口装了一个门铃（SetWindowsHookEx 装全局键盘钩子），然后告诉物业（Windows）：“以后有人按门铃，就叫我的人来处理”（把回调函数和 DLL 模块句柄交给系统）。

物业为了让你的人能处理门铃事件，会主动把你的人安排进大楼待命——这就是系统加载 HookDll.dll 到 notepad 进程的时刻。当大楼里的人按了门铃（notepad 获得焦点并按下键盘），你的人立刻在大楼内部响应（KeyboardProc 弹窗）。

特点：你的安装器全程没碰大楼一个字节，是物业（系统）自己把人请进去的。但前提是大楼里得有人按门铃（目标必须是 GUI 程序、收到键盘消息），而且你得一直守在物业办公室等（安装器不能退出，直到 UnhookWindowsHookEx）。

注入方式小结

高情商，优秀的生态和自定义编程语言；低情商，冗余代码

大多数还是绕不开LoadLibrary这一函数。三大核心 DLL：kernel32.dll（进程/线程/内存/文件）、user32.dll（窗口/消息/键鼠）、gdi32.dll（图形绘制）

显式链接 运行时按需 LoadLibrary()

+LoadLibrary
）		 写 DLL 路径进目标内存，创建远程线程执行 LoadLibraryW
，触发 DllMain		 给目标公司派一名新员工，他入职第一件事就是把你的 U 盘插进公司电脑
原生线程注入（NtCreateThreadEx
/RtlCreateUserThread
）		 同上，但绕过 kernel32 直接走 ntdll 原生接口创建远程线程 不走被装了摄像头的前台，直接拨内线总机办同一件事
APC 注入（QueueUserAPC
）		 把 LoadLibrary
排进目标线程的 APC 队列，等它进入可告警等待状态时自动执行		 不敲门，往对方待办清单塞一张便条，等他下次打盹时自己照着做
线程执行劫持（Get/SetThreadContext） 挂起线程 → 读上下文 → 写 shellcode → 改 EIP/RIP
→ 恢复线程		 趁对方睡着，把他脑子里”下一步做什么”改成你的地址，再叫醒他
消息钩子注入（SetWindowsHookEx
全局钩子）		 钩子过程所在 DLL 会被系统强制注入到产生被钩取消息的任何进程 在邮局设中转站，任何信件必须先过你手；系统为请你出面，只好把你的办公室搬进每户人家
线程局部钩子（ThreadLocalHook） 只钩目标进程内某个已加载 DLL 的导出函数，命中即在该进程执行 不给全城装窃听器，只在那栋楼的一个房间装
代码 / Shellcode 注入 只注入自包含机器码 + 打包好 API 地址的结构体，远程线程直接执行 不寄整箱货，只塞一张手写操作步骤和一张电话号码表
反射式注入（Reflective DLL Injection） 自带 ReflectiveLoader
，在内存中自行重定位、解析导入表、调 DllMain
，无需 LoadLibrary
、无文件落地		 货箱自带搬家公司，自己卸货、自己找货架、自己核对清单，全程不留快递单
模块踩踏（Module Stomping） 把已加载合法 DLL 的入口点/.text
改可写后覆盖为 shellcode，再新建线程执行该入口		 不新盖房子，把合法住户家里的人换掉，看房的一看门牌号就走了
DLL 镂空（DLL Hollowing / Module Overloading） 映射合法 DLL 后掏空原节内容、填入载荷，PE 头与模块名保留，内存属性为 MEM_IMAGE 租下合法门面，把里面的货全换成自己的，招牌照挂
节区映射注入（NtCreateSection
+MapViewOfFile
）		 以 SEC_IMAGE
创建映像节并映射进目标，再跳转入口执行		 走正规报关通道进货，单据上写着”合法映像”，不是私搭乱建
进程镂空（Process Hollowing / RunPE） 建挂起进程 → 掏空原镜像 → 写入新 PE → 改指令指针 → 恢复线程 先注册一家停业待命的空壳公司，把它的业务掏空换成你的，再宣布开业
Doppelgänging / Herpaderping 利用事务 NTFS / 先写盘后改内容，让加载器映射与磁盘内容不一致的映像 签合同时用可撤销的草稿，盖完章再把正文换掉
纤程 / 定时器 / 工作项注入 借目标进程已有的 Fiber、定时器回调、线程池执行 shellcode，不新建线程 不招新人，用公司已有的闹钟和备用工位把你的活干了
直接系统调用（Direct Syscall / Hell’s Gate） 手工取 syscall 编号直接陷入内核，绕过用户层 inline hook 绕开被改装的正门，自己从后门编号进楼
原子内核补丁（Atomic Kernel Patch） 直接改写内核内存中的函数/SSDT，使所有进程按攻击者逻辑执行 不改某家公司制度，直接改国家的法律条文
